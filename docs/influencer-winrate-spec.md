# 要件定義: インフルエンサー勝率アルゴリズム（API キー不要版）

**作成日**: 2026-07-08 / **作成者**: Fable 5（設計）・ユーザー承認待ち
**発端**: ユーザー提案「X にログインして過去 3 回分くらいのツイートを見て、勝率を判断すれば良いのでは」— 外部 AI API（Grok 枯渇・Anthropic キー不在）に依存しない、Claude Code セッション内完結の設計へ全面変更する。
**関連**: `tasks/stock_algo_kpi_loop.md`（診断 R3）・`docs/stock-algo-kpi-catalog.md` §2-G（インフルエンサー KPI 群の事前定義）・`tasks/research_pipeline.md`（旧 Grok パイプライン）

---

## 1. Why（なぜ作るか）

- 株価アルゴ本体（チャンピオン構成）は月 1 件のスナイパー型で、**「実際に当てている人間の目」という直交した情報源**が欲しい（ユーザーの当初構想の 3 本柱の 1 つ）
- 過去検証で「インフルエンサーシグナルの +20% 到達率 11〜15% ≒ ベースレート比 3 倍」という有望な暫定値が出ているが、**遡及収集バイアス込み**のため前向き（prospective）データでの再確認が必須
- 旧設計は xAI Grok API 依存で停止中。本設計は**外部 API 費用ゼロ・完全ローカル + Claude セッション**で同じ成果を得る

## 2. Who（誰が使うか）

ユーザー本人。週 1 回のランキング閲覧と、勝率上位者の新規推奨の観察。

## 3. ゴール / 非ゴール

**ゴール**
- G1: 凍結済み 37 アカウント（`data/influencer_list_frozen_2026-07-05.json`）の銘柄推奨を前向きに蓄積し、**アカウント別勝率ランキング**を週次更新する
- G2: 3 ヶ月後（2026-10 頃）に「勝率上位者の新規推奨」KPI をカタログ §2-G 定義で正式検証できるデータ量を確保する

**非ゴール**
- 完全無人化（週 1 回のセッション起動は許容。将来の launchd 化は P3 オプション）
- 新規アカウントの発見・リスト拡張（凍結リストの時点管理を壊すため。追加は日付付き新版でのみ）
- 抽出精度 100%（人間のツイートは曖昧。confidence 付きで確率的に扱う）

## 4. 成功基準（観測可能）

| # | 基準 | 測定方法 |
|---|---|---|
| S1 | 週次サイクル 1 回が 30 分以内・外部 API 費用 0 円で完走する | 実行ログ |
| S2 | 新規シグナルが既存スキーマ（signals.jsonl）互換で蓄積され、既存 634 件と連続性を保つ | `python3 -c "json..."` でスキーマ検証 |
| S3 | 勝率採点が実株価（J-Quants bars）と突合され、5 営業日/20 営業日の勝率がアカウント別に出る | weekly_scoreboard.md の生成 |
| S4 | 抽出の再現性: 同一ツイート集合に対する抽出結果が記録付き（extraction_model にセッションモデル名とプロンプト版を記録） | signals.jsonl のフィールド検査 |
| S5 | 3 ヶ月で prospective シグナル累計 ≥100 件（週 10〜40 件見込みの下限側でも到達） | 台帳カウント |

## 5. 機能要件

### F1 収集（AI 不要・実装済み資産の再利用）
- 経路: 既存 `scripts/research_influencers.py --phase collect`（Playwright + Cookie。**新規ログイン自動化は禁止** — feedback memory 準拠。Cookie は `import_chrome_cookies.py` で更新）
- 対象: 凍結 37 アカウント・8 日窓・週 1 回
- 出力: `output/research/tweets_<account>.json`（既存形式）
- 逆指標（group6 `is_contrarian: true`）のフラグを収集後に付与（`research_weekly.py` 実装済みの後処理を再利用）

### F2 シグナル抽出（Claude セッション内・本設計の核心）
- **実行主体: Claude Code セッションの Sonnet サブエージェント**（外部 API 呼び出しなし・購読内で費用ゼロ）
- 入力: 未抽出のツイート JSON（前回抽出済み tweet_url は signals.jsonl との突合でスキップ）
- 出力: 既存スキーマ互換のシグナル `{tweet_url, username, posted_at, ticker(5桁.T), direction(LONG/SHORT), confidence(0-1), matched_text, reasoning, is_contrarian 反映, signal_id}` + **`extraction_model`（例 "claude-sonnet-5/prompt-v2"）と `extracted_at` を新設フィールドとして必須記録**（§6 PIT 規律: モデル/プロンプトのバージョン凍結）
- 抽出プロンプトは `docs/prompts/influencer_signal_extraction_v2.md` として**バージョン管理されたファイルに固定**（変更時は v3 として別ファイル・台帳に切替日を記録）
- 判断規準: 銘柄コード or 一意に特定可能な銘柄名 + 明確な方向性（買い/売り/強気/弱気）があるもののみ。相場観だけ・銘柄なしは抽出しない（旧 Grok 版と同一規準）

### F3 勝率採点（AI 不要）
- 既存 `ResearchStore`/評価ロジックを再利用し、**価格ソースを yfinance から J-Quants ローカルキャッシュ（bars）に差し替え**（手元 10 年分・API 不要・上場廃止対応済み）
- 各シグナル: signal_date 翌営業日寄付エントリー → 5bd/20bd 終値で is_win 判定（既存 evaluations.jsonl とスキーマ互換）+ +20% 到達フラグ（カタログ §2-G の関心指標）。**実装（`scripts/winrate_score.py`）の出力先は `output/research/evaluations_bars.jsonl`（旧 evaluations.jsonl とは別ファイル）で、signals.jsonl から毎回全件再計算し実行のたびに上書きする（追記ではない。pending だったホライズンを埋め直すための導出データのため・2026-07-11 監査O-2修正）**
- SHORT シグナルと is_contrarian は方向反転を一貫適用

### F4 ランキング出力
- `output/research/weekly_scoreboard.md`: アカウント別（prospective のみ / 遡及分は参考欄に分離表示 — カタログ §2-G「遡及収集分は仮説出し専用」準拠）
  - 列: アカウント / prospective シグナル数 / 5bd 勝率 / 20bd 勝率 / +20% 到達率 / 平均リターン / 直近シグナル
  - 統計的注記: n<10 のアカウントは「参考」表示
  - **リスト型投稿の分離（2026-07-08追記・発見③反映）**: 同一 tweet_url から抽出された signal 件数
    （tickers_per_tweet）が 5 件以上の投稿は「リスト型」（株探ランキング転載・固定ウォッチリスト等）と
    判定し、アカウント別的中率表（メイン表）から除外する。除外分は「リスト型投稿（的中率評価対象外・
    セクター横断スクリーニング情報）」枠に件数・参考成績とともに別掲する（サイレント除外禁止）。
    閾値は signals.jsonl の tweet_url 別 signal 件数分布（1〜4件が全体の85.8%）から、2〜4銘柄の
    正当な複数銘柄言及を誤って除外しない境界として設定した（rules/20 偽陽性ガード）。判定は「抽出済み
    signal 件数」ベースの構造的指標であり、ツイート本文そのものの銘柄数や「リスト風フォーマットか」
    という意味的判定ではない（抽出漏れがあれば境界がブレうるため、境界付近＝4〜6銘柄のケースは
    §8 ランブックで週次抜き取り監査する）。
- ユーザー向け 1 行サマリ（「今週の新規シグナル N 件・勝率首位は@X」）を paper_today.md にも 1 行連携（表示のみ）— **未実装（P2）**。paper_today.md は daily_screen.py が毎朝生成するため、この連携は稼働中の朝ジョブ側の改修が必要で別タスクとする（2026-07-08 Codexレビュー②で spec と実装の乖離を指摘され明示化）

### F5 KPI 連携（将来・P2 以降）
- 蓄積 3 ヶ月後、カタログ §2-G「インフルエンサー実績スコア」（ローリング勝率上位者の新規 LONG 言及）を既存ハーネス（kpi_event_study.py）で正式検証
- 合格すればペーパートレード watchlist に observation として追加

### F6 運用トリガー
- P1: ユーザーが週 1 回「インフルエンサー週次回して」と言う（このセッション or 新セッション。手順は本 spec §8 のランブック）
- P3（任意・後日）: 既存の scheduled-prompt 基盤（`vault-prompt-runner.sh` + launchd。ユーザー環境で稼働実績あり）に週次プロンプトとして登録し完全自動化

## 6. 非機能要件・制約

- **PIT 規律**: 評価は凍結日（2026-07-05）以降の投稿のみ。遡及分（〜4/24 収集の 634 件）は仮説出し専用の別枠。extraction_model の切替は台帳記録
- **X 利用の安全**: 収集は既存 Cookie 経路のみ・スクロール数控えめ（bot 検知回避・アカウント保全優先）。**Cookie 失効時は自動再ログインせず停止してユーザーに Chrome 経由更新を依頼**
- **コスト**: 外部 API 0 円。Claude 使用はセッション内サブエージェント（購読内）
- **Canonical**: 収集・Store・評価は既存実装を再利用。新規コードは「差し替え点」（価格ソース・抽出アダプタ・scoreboard 生成）に限定

## 7. 受入テスト（P1 完了の定義）

1. **E2E 1 サイクル**: 収集（37 アカウント）→ 未抽出ツイートの抽出（サブエージェント）→ スキーマ検証 → 採点 → weekly_scoreboard.md 生成、が一連で完走
2. 抽出品質の抜き取り: 抽出シグナル 5 件を原文ツイートと目視突合（銘柄・方向・confidence の妥当性）+ 非抽出の妥当性 3 件（相場観のみのツイートが正しくスキップされているか）
3. 採点の手動照合 1 件: 任意のシグナルの entry/exit/is_win を bars から独立再計算し一致
4. 既存 634 件の遡及データが「参考枠」に正しく分離表示される
5. 週次ランブック（§8）どおりに第三者（別セッションの Claude）が再実行できる

## 8. 週次ランブック（P1 納品物・実行はユーザーの一言でよい・2026-07-11 監査O-1/O-2で実装スクリプト名に合わせ全面書き直し）

**前提（本ランブックの対象外・別途稼働中）**: ツイート収集自体（F1）は
`scripts/research_influencers.py --phase collect`（Playwright + Cookie。凍結37アカウント・
8日窓）が既存資産として別途実行される。本ランブックは収集済みの `output/research/tweets_*.json`
を入力として、抽出〜採点〜ランキング化までの5段を実行する。

```
ユーザー:「インフルエンサー週次回して」
→ Claude が実行:
  1. `python3 scripts/winrate_worklist.py`
     → signals.jsonl 未抽出分を output/research/extraction_worklist.json に整形出力
  2. worklist 件数を確認し、多い場合はサブエージェントに渡す単位を分割する
     （バッチ分割目安: 1回で全件、または多い場合は分割して複数回。
     docs/prompts/influencer_signal_extraction_v2.md 冒頭の運用注記どおり。
     固定の件数閾値は設けていない — 1回のセッション内サブエージェント呼び出しで
     処理しきれる分量かどうかで判断する）
  3. セッション内 Sonnet サブエージェントが `docs/prompts/influencer_signal_extraction_v2.md`
     （プロンプト v2 固定）に従い、各バッチの worklist をシグナルJSON配列として抽出・ファイル出力
  4. `python3 scripts/winrate_ingest.py --input <抽出結果JSONのパス>`
     → スキーマ検証 → signals.jsonl へ重複排除 append（signal_id で排除）
  5. `python3 scripts/winrate_score.py`
     → J-Quants bars で採点 → output/research/evaluations_bars.jsonl を
       signals.jsonl から全件再計算し**上書き**（追記ではない）
     → output/research/weekly_scoreboard.md 更新（vault ミラーへも転写）
     → ユーザーへ 1 行サマリ報告
  6. （抜き取り監査）tickers_per_tweet が 4〜6 件の境界付近シグナルを数件、原文ツイートと目視突合し
     リスト型/非リスト型の判定が意味的にも妥当か確認する（F4 リスト型分離の誤判定検知）
```

## 9. Phase 分解

| Phase | 内容 | 規模 |
|---|---|---|
| **P1（今回）** | 抽出アダプタ（セッション内抽出の入出力整形）+ 価格ソース差し替え + scoreboard 生成 + 受入テスト E2E 1 回（今バックグラウンドで収集中のデータを使用） | ビルダー 1 名 + 抽出サブエージェント |
| P2 | 3 ヶ月蓄積 → §2-G KPI 正式検証（ハーネス再利用） | 蓄積待ち |
| P3（任意） | scheduled-prompt 化による完全自動化 | 小 |

## 10. リスクと対応

| リスク | 対応 |
|---|---|
| セッション内抽出の一貫性（週によって判断が揺れる） | プロンプトのファイル固定 + extraction_model 記録 + 抜き取り監査を週次ランブックに含める |
| Cookie 失効 | 停止して依頼（自動ログイン禁止）。maaaki は 2026-07-08 時点で生存確認済み |
| ツイート削除による生存バイアス | prospective 運用では収集が週次のため影響最小（8 日窓内の削除のみ欠落）。収集済み分は不変 |
| 37 アカウントの偏り（大半がシグナル 0 件） | 3 ヶ月時点でシグナル実績のあるアカウントに絞る棚卸しを P2 で実施（凍結リストの日付付き改版として） |
| リスト型投稿（@kazzn_blog 株探転載・@serikura 固定リスト等）の的中率が個別アカウントの判断スキルとして水増し評価される | tickers_per_tweet≥5 を「リスト型」として自動分離・メイン表から除外＋別枠で参考表示（F4・2026-07-08追記） |
