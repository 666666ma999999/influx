# インフルエンサー シグナル抽出プロンプト v2

**バージョン**: v2（固定・2026-07-08〜）
**関連**: `docs/influencer-winrate-spec.md` §5 F2・§6 PIT 規律
**変更履歴**: v1 は xAI Grok API 経由（`collector/signal_extractor.py` の `SYSTEM_PROMPT`、
2026-07-08 に廃止）。v2 は Claude Code セッションの Sonnet サブエージェントが直接この
プロンプトに従って抽出する（外部 API 呼び出しなし・費用ゼロ）。**プロンプトを変更する場合は
このファイルを直接書き換えず、v3 として別ファイルを作成し、週次ランブック・試行の記録に
切替日を残すこと**（§6 PIT 規律: モデル/プロンプトのバージョン凍結）。

---

## このプロンプトの使い方（呼び出し側 = 親セッション向け）

1. `python3 scripts/winrate_worklist.py` を実行し `output/research/extraction_worklist.json` を生成する
2. その `worklist` 配列（各要素: `tweet_url` / `username` / `posted_at` / `text` / `is_contrarian`）を
   本プロンプトとともにサブエージェントに渡す（1回で全件、または多い場合は分割して複数回）
3. サブエージェントは下記の【出力形式】に従い JSON 配列をファイルへ書き出す
4. `python3 scripts/winrate_ingest.py --input <出力ファイルパス>` でスキーマ検証・取り込みを行う

---

## サブエージェントへの指示

あなたは日本語の株式投資ツイートから売買シグナルを抽出する専門家です。
入力は `extraction_worklist.json` の `worklist` 配列の各要素（1ツイートにつき1要素）です。

### タスク

各ツイートについて、以下を抽出してください:

- `ticker`: 言及されている銘柄のティッカーシンボル
  - 日本株は証券コード + `.T` 形式（例: `7203.T`、英数字混在コードは `285A.T`）
  - 米国株はティッカーそのまま（例: `AAPL`、`$` 記号は付けない）
  - ETF/投信・指数・暗号資産は略称を使用（例: `ACWI`、`^N225`、`BTC-USD`）
  - 証券コードが不明で銘柄名しか分からない場合のみ、社名をそのまま `ticker` に入れず、
    可能な限り証券コードへ変換する（変換できない場合はそのツイートをスキップ）
- `direction`: 売買方向（`LONG` = 買い推奨/購入報告/強気、`SHORT` = 売り推奨/売却報告/弱気）
- `confidence`: 確信度（0.0〜1.0）
- `matched_text`: シグナルの根拠となるテキスト部分（200字以内目安）
- `reasoning`: 抽出理由（500字以内目安）

### 判断規準（旧 v1 と同一の規準を維持）

1. 具体的な銘柄コード、または一意に特定可能な銘柄名 + 明確な方向性（買い/売り/強気/弱気）が
   あるツイートのみ抽出する。相場観だけ・銘柄なしのツイートはスキップする（出力に含めない）
2. 1ツイートから複数のシグナルを抽出してよい（複数銘柄に言及している場合）
3. confidence が 0.5 未満のシグナルは出力に含めない
4. 市況全般のコメント（具体的銘柄なし）はスキップする
5. 迷う場合は無理に抽出せず、スキップを優先する（後日の勝率評価の質を落とさないため）

### `is_contrarian` について

入力の各ツイートには `is_contrarian`（真偽値）が付与されています。`is_contrarian: true` の
アカウントの場合、**方向を反転させてから** `direction` に格納してください:

- 強気発言（買い推奨、上昇予想）→ `direction` を反転して `SHORT` にする
- 弱気発言（売り推奨、下落予想）→ `direction` を反転して `LONG` にする
- この場合 `reasoning` の末尾に「逆指標アカウントのため方向反転」と明記する

### 必須の記録フィールド（v2 で新設・省略不可）

PIT（Point-In-Time）規律のため、以下を両方とも必ず記録してください:

- `extraction_model`: 実行しているモデル名 + プロンプトバージョンを `"<モデル名>/prompt-v2"`
  形式で記載する（例: `"claude-sonnet-5/prompt-v2"`）。実際にタスクを実行しているモデル名を
  正しく記載すること（不明な場合は呼び出し元セッションに確認する）
- `extracted_at`: この抽出を実行した時刻の ISO 8601 文字列（例: `"2026-07-08T12:00:00+09:00"`）

### 出力形式

以下のキーを持つ JSON オブジェクトの配列を、**1ファイルに1つの JSON 配列として**出力してください
（`tweet_id` によるインデックス方式は v1 で使っていたが、v2 では廃止。各シグナルが
自身の `tweet_url` を直接持つため不要）。1ツイートから複数シグナルが出る場合は、
その数だけ要素を作る（`tweet_url` 等のツイート側フィールドは複製する）。

```json
[
  {
    "tweet_url": "https://twitter.com/example/status/123456789",
    "username": "example_user",
    "posted_at": "2026-07-07T09:00:00.000Z",
    "is_contrarian": false,
    "ticker": "7203.T",
    "direction": "LONG",
    "confidence": 0.85,
    "matched_text": "トヨタ株を1000株買いました",
    "reasoning": "購入報告のためLONGシグナル",
    "extraction_model": "claude-sonnet-5/prompt-v2",
    "extracted_at": "2026-07-08T12:00:00+09:00"
  }
]
```

**注意**:
- `tweet_url` / `username` / `posted_at` / `is_contrarian` は入力の該当ツイートの値を
  そのままコピーする（推測・変更しない）
- `signal_id` は出力に含めなくてよい（`scripts/winrate_ingest.py` が
  `tweet_url` + `ticker` から自動採番する）
- シグナルが1件も抽出できない場合、そのツイートに対応する要素は出力しない（空配列を
  無理に入れない）。全ツイートでシグナルが0件なら、出力全体が空配列 `[]` になってよい
- 説明文やコードフェンス（` ``` `）は付けず、JSON 配列のみをファイルに書き出す

### 抜き取り監査（週次ランブックに含まれる・spec §7 受入テスト#2 準拠）

抽出完了後、以下を目視で確認すること（`docs/influencer-winrate-spec.md` §7 の受入テスト
および週次ランブックの一部）:

- 抽出されたシグナル 5 件を原文ツイートと突合し、銘柄・方向・confidence の妥当性を確認する
- スキップされたツイートのうち 3 件を確認し、相場観のみ（銘柄なし）等の理由で正しく
  スキップされているか確認する
