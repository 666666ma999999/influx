## 0. ゴール定義（✅ 2026-07-05 ユーザー確定）

> **目標イベント（確定）**: シグナル判定日 T の翌営業日始値でエントリーし、**20営業日後の終値が +20% 以上**（株式分割調整済み株価で判定）

**確定事項**（当初依頼の「130%」「120%」表記ゆれは以下に一本化。2026-07-05 ユーザー回答）:
1. 閾値: **+20%**（+30% はベースレート計測後に比較検討する二次候補）
2. 判定: **20営業日後の終値**（高値タッチ版は §6 手順3(c) の感度確認としてのみ計測）
3. エントリー価格: **T+1営業日の始値**（T終値エントリーはルックアヘッドのため不採用）
4. 負け側: **損切り -5〜-8% の運用ルールを前提とする**。具体水準は §6 手順3 の MAE・安値タッチ率・損切り別EV計測で確定し、バックテスト仕様に含める
5. 成功定義: **EVベースを許容**（勝率60%単独には固定しない）。§6 のベースレート計測完了をマイルストーンとし、達成可能なリフトの相場観とあわせて合格基準（§6 評価プロトコル3）の最終数値を確定する

### 用語ミニ注釈（非エンジニア向け）
- **PIT（point-in-time）**: 「過去のその日に実際に知り得た情報だけ」で計算できること。バックテストの生命線
- **ルックアヘッドバイアス**: 当時まだ公表されていなかった情報を使ってしまう誤り。成績が幻の高さになる
- **サバイバーシップバイアス**: 上場廃止された銘柄を検証から漏らす誤り。これも成績が水増しされる
- **in-sample / holdout（OOS）**: パラメータ探索に使うデータと、最後に一度だけ答え合わせに使う「封印」データの分割。封印を何度も開けて見ると探索と同じになり、成績が幻になる
- **データスヌーピング（多重検定）**: たくさんの仮説・閾値を試すほど、偶然だけで「効いて見える」ものが必ず出てくる問題。試行回数の記録と割引評価で防ぐ
- **リフト倍率**: KPIで絞った母集団の到達率 ÷ 素のベースレート。「何倍濃縮できたか」
- **MAE（最大逆行幅）**: 保有期間中に最も不利な方向へ動いた幅。損切りルール設計の材料
- **PEAD**: 決算発表後も株価がじわじわ同方向に動き続ける現象（決算後ドリフト）
- **信用倍率**: 信用買い残÷信用売り残。1未満=売り方優勢=「踏み上げ」（空売りの買い戻しによる急騰）余地
- **逆日歩**: 空売りする人が払う追加コスト。発生=株の借り手不足=売り方が苦しいサイン
- **レジーム**: 相場全体の地合い（強気/弱気）の状態

## 1. カタログの読み方

- **優先度 v0**: 最初のバックテストループに投入（データ入手容易×仮説強・計14個 → §3）
- **優先度 v1**: 2周目以降。データ整備か仮説検証の前提が1つ必要
- **優先度 hold**: 現時点で投入しない（データ有償・日本で非有効の実証・機械化難度大のいずれか）
- 各KPIの計算定義は「機械的に再計算できる式・条件」まで落としてある。閾値（-10%、2倍等）はすべて**グリッドサーチ対象の初期値**であり固定仕様ではない。ただしグリッドサーチは**§6の評価プロトコル（in-sample限定・試行台帳・事前合格基準）の凍結後にのみ**実行する
- **定義の共通規約**（全KPI・実装時の暗黙判断を排除）:
  - 「出来高>20日平均×N」は明記なき限り**売買代金（TurnoverValue）基準**。株数を使う場合は**分割調整済み株数（AdjustmentVolume）**と明記する（未調整株数は分割を跨ぐと平均が壊れるため使用禁止）
  - シグナル確定時点は明記なき限り**T終値**、エントリーは**T+1寄付**。翌日足の確認を含むKPIは確定がT+1終値・エントリーがT+2寄付となるため個別に明記する
  - 複数条件は**括弧付き論理式**で表記し、AND/ORの結合順の曖昧さを残さない
  - 各KPIの実装仕様書には必須欄として「使用系列（調整/未調整・株数/売買代金）」「シグナル確定時点」「エントリー日」「括弧付き論理式」を設ける

### B. 需給（信用・空売り・貸借）

## 3. v0推奨セット（最初のループに投入する14個）

### 選定の考え方
1. **データ入手容易性**: J-Quants Standard（¥3,300/月）+ EDINET API（無料）+ 適時開示アドオンだけで全て計算できるものに限定。有償コンセンサス・3年制限の日証金・テーマ辞書構築が必要なものは除外。ただし**適時開示アドオンは実在・遡及範囲が未確認**のため、依存するのは#12のみに留め、**#12なしでも#8〜#11＋株価系だけで最初のループが成立する構成**にしてある
2. **仮説強度と日本市場実証の反映**: 「日本はモメンタムが弱くリバーサルが強い」（Asness 2011）に従い、順張りモメンタム系は素の形では入れず、**リバーサル・イベント・需給転換・出来高ショック**を主軸にした。+20%/1ヶ月を直接狙える「点火系」（出来高ショック・上方修正・PEAD・スクイーズ）を厚くし、リスク調整後リターン系（低ボラ等）は外した
3. **相互の独立性**: 「価格の位置（リバーサル/新高値）」「出来高（ショック）」「需給（信用・空売り）」「イベント（決算・開示）」「フィルタ（過熱・地合い）」の5系統から重ならないよう選抜。同系統で相関が高いもの（25日乖離と短期リバーサル等）は代表1本に絞った

### 複合KPIの文法とシグナル頻度予算（ループ開始前に固定）

本プロジェクトの目的は複合KPIパターンの発見であり、単体KPI定義だけでは各周回の比較可能性が保てない。以下を固定する。

- **3層構造の文法**: 複合は「**母集団生成KPI**（短期リバーサル/新高値/出来高ショック/イベント系）× **負けフィルタ**（MAX/買残/希薄化/地合い）× **増幅条件**（決算接近・空売り残高等）」の3層に限定する。層内はOR・層間はANDを基本とし、スコア加重を導入する場合も同じ3層の枠内で行う
- **段階的な層追加**: まず2層（母集団×フィルタ1個）から始め、層・条件を1つ増やすたびに**シグナル数とCI幅を必ず報告**する（ANDを重ねるほどシグナル数が減って検定力を失うトレードオフの明示管理。§6評価プロトコルと連動）
- **最低シグナル頻度**: 合格要件に**月5銘柄以上**を追加する（勝率60%でも年3シグナルでは運用不能）
- **同時点火の扱い**: 複数KPIが同一銘柄・同一時点で点火した場合は「1銘柄1エントリー」に統一し、点火したKPI集合を属性として記録する（二重計上防止と、後の複合パターン分析の材料化を兼ねる）

## 4. 負けパターン定義に使う指標（勝率60%の裏の40%を特徴づける候補）

バックテストで負けトレード群（20営業日後 -5%以下）に共通する特徴を機械的に抽出するための候補リスト。各v0 KPIの「勝ちサンプル vs 負けサンプル」でこれらの分布差を取るのが2周目の分析。

## 6. 最初に計測すべきベースレートと評価プロトコル（全ループの前提）

「勝率60%」が凄いのかどうかは、**TOP500ユニバースで『1ヶ月+20%』が素で起きる確率（ベースレート）**が分からないと判定できない。市場全体では通常数%とみられ、influxインフルエンサーシグナルの+20%到達率11〜15%が「有望」かどうかもこの計測で初めて確定する。**どのKPI検証よりも先にこれを実行する。**

> **✅ 計測結果（2026-07-06 確定・`scripts/measure_base_rate.py`）**: 全期間(2016-08〜2026-05・118ヶ月・n=58,497)の素の P(+20%/20bd終値) = **4.1%**（in-sample 2016-2022 = 3.7%）。P(+30%)=1.7% / P(高値タッチ+20%)=8.5% / P(-5%以下)=24.9% / EV(0.3%コスト込): 損切りなし+0.6%・-8%損切り+0.2% / -8%タッチ率33.5%。w126(6ヶ月売買代金)ユニバースでも3.9%とほぼ同値=ユニバース定義に頑健。**ユニバース新規流入銘柄は6.9% vs 既存3.5%（約2倍・両ユニバース定義で頑健）**。**bear地合いの方が高い（4.7% vs bull 3.9%）= v0 #14のbull限定ゲートは+20%狙いに逆効果の可能性**。influxシグナルの+20%到達11〜15%はベースレート比約3倍=実は優秀の可能性が確定。勝率60%は素の14.6倍で非現実 → 成功定義はEV型（合格=リフト≥2倍[CI下限>1.5]かつ月次EV≥+3%かつ月5銘柄以上）を採用（§0-5確定・2026-07-06）。
>
> **2026-07-06 追記（14試行のマイルストーンレビューでユーザー決定・二段階化）**: 上記を「**理想ライン**」とし、「**運用開始ライン**」= リフトCI下限>1.2・EV≥+1%/月（コスト・損切り込）・月5銘柄以上 を新設。**PEAD初動（リフト1.89[1.37,2.56]・EV+1.45%・月9.1件）が運用開始ラインを充足 → 運用候補v1**。進め方は併走: 第7周で信用/空売り系（#5-#7）を検証 → 最終候補リスト確定 → holdout(2023-2026)を**1回だけ**開封して最終確認 → 運用設計へ。

同時に、ベースレートが数%なら「P(+20%)≥60%」は**リフト12倍超**の要求であることを直視する。学術的に最も頑健なイベント（大幅上方修正・PEAD）の文献リフトでもこの水準には遠く及ばない。したがって**ベースレート計測の完了を目標再交渉のマイルストーン**と定め、その時点で (a) 各v0 KPIの文献リフト実績にもとづく「達成可能なリフトの相場観」(b) 勝率型（P≥60%）とEV型（例: 勝率35%・平均勝ち+25%・平均負け-7%でEV+4%超）の成功定義の選択肢、を提示して§0の確認事項5を確定させてから本検証に進む。

### 計測手順（J-Quants Standardのみで完結）

1. **月次ユニバース再構築**: 各月末営業日Tごとに、(a) 取引カレンダーでT以前の直近21営業日を確定 → (b) `daily_quotes`（date指定×21日）で全銘柄のTurnoverValue（売買代金実額）を合計 → (c) `listed_info`（date=T）で当時の市場区分により普通株のみにフィルタ（ETF/REIT除外）→ (d) 売買代金降順の上位500銘柄を `universe_YYYYMM` として保存。※「現在の上場銘柄リスト」から出発しない（サバイバーシップバイアス防止）。あわせて**月次入替率（churn）を計測・記録**する
2. **フォワードリターン計算**: 各ユニバース銘柄について、T+1営業日始値エントリー → 20営業日後終値（調整済み株価）のリターンを計算。**配当補正**: J-Quantsの調整済み株価は分割のみ調整で配当は未調整のため、ウィンドウ内に権利落ち日がある場合は配当額を加算した**実質トータルリターン**で判定する（未補正だと高配当銘柄で2〜4%の系統的過小評価が3月・9月に集中し、+20%判定と低PBR系KPIの評価を歪める）。⚠️ 2026-07-05実査: **配当金情報APIはPremium限定でStandardには含まれない**。実装時は (a) Standardの財務情報サマリー内の配当関連フィールドで代替可能か確認 → (b) 不可なら配当未補正版でベースレートを先に算出し、高配当上位銘柄サンプルで補正影響を感度計測 → (c) 影響が+20%判定を歪める水準ならPremium昇格を検討、の順で対処する。**期中上場廃止**: 「最終取引日終値で決済」と定義し欠損扱いにしない（欠損扱い=バイアス再混入）。ただし**TOB・完全子会社化による廃止は公開買付価格ベースの決済**として扱う（プレミアム決済は+20%勝ち扱いになるべきケースがある）。併合・減資は調整係数で処理
3. **ベースレート集計と負け側のパス依存計測**: 月ごとに「+20%以上到達した銘柄の割合」を算出。あわせて (a) リターン分布全体（中央値・-5%以下の割合＝負け側の素の確率）(b) +30%到達率（ゴール定義確認用）(c) 高値タッチ版の到達率（判定方式の感度確認用）(d) **MAE/MFE（期間中最大逆行・最大順行）**(e) **-8%/-10%/-15%の安値タッチ率** (f) **損切りルール別EV（なし/-8%/-10%の2〜3種で執行シミュレーション）**も出す。EV例の「負け側-5%」が達成可能な損切り水準かを**KPI検証開始前にここで確定**する（§0確認事項4の裏付け）
4. **レジーム別分解**: TOPIX>200日線の月 vs 以下の月でベースレートを分け、地合いによる変動幅を把握（influxの2.5ヶ月データの地合い分離にもこの表を使う）
5. **ユニバース入替バイアスの分解**: 直近21営業日売買代金による選抜は「直前に出来高と株価が噴いた銘柄」を毎月新規流入させるため、(a) ベースレートとすべてのKPIリフトを**「既存メンバー（3ヶ月以上連続在籍）」vs「新規流入銘柄」に分けて報告**する（短期リバーサルの成績が入替効果と混同される・出来高ショックが「ユニバース入り」イベントと二重計上になる・入替銘柄の負のドリフトでベースレートが歪む、の3点を分離するため）(b) 感度確認としてユニバース定義を**6ヶ月平均売買代金**でも再計算し、乖離が大きいKPIは「ユニバース定義への過適合」と判定する
6. **合格ラインの設定**: 以後の全KPIは「そのKPIで絞った母集団の+20%到達率 ÷ 同月のベースレート」（リフト倍率）と勝率・EVで評価する。EV計算には**売買コスト往復0.2〜0.5%とストップ高翌日約定ルール**（S高で買えない日はエントリー翌日に繰り延べ）を必ず織り込む

### 評価プロトコル凍結（全KPI検証共通・着手前に固定）

約50KPI×閾値グリッドサーチ×レジーム分割を無規律に回せば、偶然だけで「偽の勝率60%」がほぼ確実に複数見つかり、ループを回すほど幻の必勝パターンに確信を深めることになる。これを防ぐため、以下を**最初のKPI検証より前に凍結**し、以後変更しない。

1. **標本分割**: J-Quants Standardの遡及10年を **in-sample（2016〜2022）** と **holdout（2023〜2026・ロック）** に分割する。閾値グリッドサーチ・KPI選抜・複合パターン探索はin-sampleのみで行い、holdoutは選抜済み候補の**最終確認に1回だけ**使う（開封のたびに探索データ化することを禁止）
2. **試行台帳**: すべての試行（KPI×閾値×ユニバース定義×レジーム分割×結果）を台帳に記録し、**試行数に応じた割引評価**を行う（最低限、Bonferroni的な感度確認: 有意水準÷累積試行数でも結論が保つかをチェック）
3. **合格基準の事前定義**: KPI（単体・複合とも）の合格は以下を**すべて**満たした場合のみ。①シグナル数 n≥100 ②24ヶ月以上に分散 ③強気/弱気の両レジームをまたぐ ④リフト倍率の**月次ブロック・ブートストラップCI下限>1.5** ⑤holdoutで方向一致。満たすまでは「合格」でも「不合格」でもなく**判定保留**とし、早期の結論を出さない
4. **検証方式**: 「1ヶ月前→2ヶ月前→3ヶ月前…」と検証期間を遡って伸ばすwalk-back方式は**採らない**（初期の結論が単一レジーム＝直近地合いの極少サンプルに支配される）。最初から**全履歴一括のイベントスタディ**として実行する
5. **CIの算出方法**: 月次コホート500銘柄は市場要因で横断相関しており、20営業日ウィンドウを日次でずらすと重複ウィンドウの系列相関も加わる。独立試行を仮定した二項CIは実際より大幅に狭くなるため使わず、**月次ブロック・ブートストラップ**でCIを算出する
6. **シグナル頻度予算**: §3の複合文法と連動し、合格要件に最低シグナル頻度（月5銘柄以上）を含める。層を追加するたびにシグナル数とCI幅を台帳に記録する

### 横断的なPIT実装ルール（全KPI共通・再掲）
- 財務系は「決算期末日」でなく**開示日（DisclosedDate/提出日時）**基準。引け後開示は翌営業日から有効
- 週次信用残は公表日（基準日+2〜3営業日）以降のみ使用。投資部門別売買状況は公表日（翌週木曜）以降のみ使用

- リターン判定は権利落ち跨ぎの配当加算・TOB廃止の公開買付価格決済を含む（手順2の定義に統一）
- 出来高条件は売買代金基準（株数なら調整済み株数）、シグナル確定時点・エントリー日・括弧付き論理式を各KPI仕様書の必須欄とする（§1の共通規約。暗黙の実装判断は再現性と後知恵混入の温床）
- テーマ辞書・アクティビスト辞書・**influxアカウントリスト**は年次/日付バージョンで時点管理
