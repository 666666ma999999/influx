# price-source-onboarding — 価格系列を1本足す

## 置き場所（実在確認済み）

| | |
|---|---|
| 設定（系列の定義＋受益カード） | `configs/price_universe_sources.json` |
| 設計の正本 | `docs/price-watch-universe.md` |
| 収集 | `scripts/price_watch_collect.py` |
| 検査・表示 | `scripts/price_universe_check.py` |
| 前向き記録 | `scripts/price_watch_forward.py` |
| 週次実行 | launchd `com.influx.price-watch` → `scripts/price_universe_run.sh` |

## 手順

### 1. 一次ソースを実証してから決める

**「取れそう」で設定に書かない。** 実際に叩いて、数値が返ることを確認する。

⚠️ **tradingeconomics は存在しないスラッグにも 200 を返す。** ステータスコードだけで判定すると、ずっと空を掴み続ける。**行スコープ＋ラベル一致**で中身を見て判定する（既存の `_comment` に明記されている落とし穴）。

無料で取れることを優先する。有料ソースを提案するときは、競合3社以上＋「既存の仕組みでやる／やらない」を並べた比較表を、勧める最初のメッセージに付ける。

### 2. カード形式 v2 で設定に足す

系列だけでなく、**受益銘柄のカード**（`btype` / `sign` / `evidence` / `verified` / `tier`）まで書く。
海外上場を載せる場合は `market`（JP以外）・`ticker`・`benchmark` の3つも必須（§16w・欠けると通知にも集計にも出ない）。
食品系列で上昇を通したい場合は `pass_through: true` + 正味プラスの実測が要る（§16v）。
カードの書き方と5関門は `beneficiary-attribution` スキルへ。**カードが書けないなら台帳に載せない。**

### 3. パーサの落とし穴を潰す

| 落とし穴 | ガード |
|---|---|
| 列ズレ | ヘッダの順序を一致検査する |
| 0件なのに成功扱い | 有効行が1つも無ければ**失敗として扱う**（空で exit 0 を返さない） |
| 値の桁・単位違い | 想定レンジ外の値は弾く（セマンティック検査） |
| 取れなくなったのに気づかない | 前回値との差・更新日の鮮度を見る |

### 4. 敵対レビューの固定観点

追加のレビューでは、必ずこの3点を聞く:

1. **データ汚染** — 別系列・別単位の値が混ざらないか
2. **誤発火** — 閾値が緩すぎて毎週鳴らないか
3. **永久沈黙** — 逆に、取得が壊れても誰も気づかない構造になっていないか

### 5. 週次ジョブに載るまでが1周

commit したら、`launchctl list | grep com.influx.price-watch` で終了コードを確認する（0 以外なら未完）。
初回の自動実行が通るまで「完了」と言わない — **新規登録したジョブが初回実行で落ちて誰も気づかない**のは、この環境で実際に複数回起きている。
