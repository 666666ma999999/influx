# x-post-to-kpi — X投稿 → KPI仮説の取り込み

## 1. まず読み切る（判定より先・ここを飛ばさない）

投稿の**4点すべて**を読む:

1. 本文
2. **長文フィールド**（`note_tweet`）— 本文が途中で切れていることがある
3. **添付メディア（図・画像）** — 核心の数値が図の中にあることがある
4. スレッドの続き

本文中に「この図」「下記」「続きは」があれば、**参照先が未読という警報**。そこで止まって取りに行く。

> 実害（2026-08-03）: 本文だけ読んで「既知の話」と判定したが、核心データは添付図の中にあり、ユーザーに2回指摘された。同じURLを3回投げ直させた事例もある。

## 2. KPI仮説の形に翻訳する

投稿の主張を、**検証できる文**に直す。

- ❌「決算サプライズは効く」
- ⭕「決算発表後◯営業日以内に、売上が事前予想を◯%上回った銘柄は、20営業日後の終値が…」

数字（窓・閾値・母集団）が投稿に書かれていなければ、**書かれていないと明記する**。勝手に補わない。

## 3. 既存カタログと突き合わせる

`docs/stock-algo-kpi-catalog.md` を実読して確認する:

- **§2** に同じ・似た仮説が既にないか
- **§8-6（墓場）** に**すでに落ちた仮説**として載っていないか ← ここを見ずに再提案するのが最頻の無駄

既出なら「既出です。どこに載っているか」を返して終わる。

## 4. 実装できるか判定する

| 見る点 | 落ちる例 |
|---|---|
| データがあるか | 必要な系列を持っていない |
| **PIT（判定時点で知り得たか）** | 後から修正された値を使ってしまう |
| ルックアヘッド | 未来の情報が混ざる |

実装できないなら、その理由を書いて**保留在庫**へ。捨てずに理由を残す。

## 5. 通ったら事前登録へ

`docs/stock-algo-kpi-catalog.md` §7 の事前登録に接続する。
