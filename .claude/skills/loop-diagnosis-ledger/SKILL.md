# loop-diagnosis-ledger — 診断の再演を止める

ユーザー自身が「**いつも同じ結論に行き着く**」と指摘している領域。1回の診断は数万トークン規模なので、7回以上の再演はそのまま無駄になっている。

## 手順（この順を守る）

### 1. 議論を始める前に、既決を出す

新しい2モデル議論を**立ち上げる前に**、過去の診断で確定した論点を並べて提示する。

読む先:
- `docs/stock-algo-kpi-catalog.md` **§8-6（墓場）** — 落ちた仮説とその理由
- `docs/winrate-ev-summary.md` — 勝率とEVの現在地
- vault `wiki/meta/decisions.md` の influx 関連エントリ

### 2. 差分だけを新しい論点にする

既決を「所与」として渡し、**それでも説明がつかない部分**だけをレビュー対象にする。
既決の再診断はさせない（例外は下の3つだけ）。

**再診断してよい場合**:
- 既決を覆す新しい実測・証拠が出た
- 既決の前提となったファイル・数値が変わった
- ユーザーが「前提から見直して」と明示した

### 3. 出た結論は台帳へ戻す

診断の結論を**その場のチャットで終わらせない**。既決として1行追記する（G1, G2... と採番）。
これをしないと、次のセッションでまた同じ議論が立ち上がる。

書き戻し先は既存ファイル（上記の §8-6 や winrate-ev-summary）。**新しい台帳ファイルを作らない**。

## 台帳の1行の形

```
G7 | 2026-08-04 | 勝ちレシピが増えない主因は「候補の枯渇」ではなく「凍結前の覗き見で候補が失格になる」 | 根拠: 41周中◯周が同因で NO-GO | 状態: 確定
```

## 注意

- **診断の結論を「打ち手」で終わらせない。** 何を次の周で変えるかまで書く
- 同じ結論に3回到達したら、それは診断の問題ではなく**実行が律速**している合図。診断を続けずに実行側へ移す
