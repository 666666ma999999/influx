# daily-reco-answer — 今日の推奨銘柄の答え方

## 読むファイル（正本・手書き禁止の自動生成物）

| ファイル | 中身 |
|---|---|
| `output/daily_reco.md` | 本日のレコメンド（表示専用・毎朝自動更新） |
| `output/daily_reco_summary.json` | 同じ内容の機械可読版 |
| `output/paper_today.md` | ペーパートレードの本日分 |
| `output/paper_scoreboard.md` | ペーパーの累計成績 |

生成側は `scripts/build_daily_reco.py` と launchd。**このファイル群を手で書き換えない。**

## 答えるときに必ず入れる4点

1. **正式合格が何本か** — `## ✅ 実戦投入可（正式合格）` の本数。**0本ならまずそう言う**
2. **銘柄は「コード＋社名」で書く** — `62680` だけでは伝わらない。`62680 ナブテスコ` と書く
3. **発火した系統と参考EV** — どの系統で拾ったのか。EV は下限（信頼区間の下側）まで添える
4. **状態** — エントリー前／保有中(ペーパー)

## 絶対に言ってはいけないこと

- **金額・枚数・倍率・配分を提案しない**（catalog §0付記II の一方向ルール）
- 正式合格0本の間は、**載っている候補はすべて「ペーパー提案＝前向き検証中」**。実弾の推奨として書かない
- daily_reco.md は**表示層**であって、判定・台帳・αには一切影響しない。ここの数字を根拠に別の結論を作らない

## ファイルが古い／無いとき

日付を確認し、**「今日の分はまだ生成されていない」と先に言う**。古い内容をそのまま今日の推奨として出さない。
再生成が要るなら `scripts/build_daily_reco.py` の実行と launchd の状態（`launchctl list | grep influx`）を確認する。

## 回答テンプレ

```
正式合格: 0本（ペーパー検証中）
有力候補: 11銘柄（直近5営業日の発火）

上位3件:
  1. 62680 ナブテスコ — 売上サプライズ・利益サプライズ(上昇中) / 2系統
     参考EV +0.18%[下限 -2.09%] (n=282) / エントリー前
  ...

出所: output/daily_reco.md（本日更新分）
```
