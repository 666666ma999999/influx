## 対象と数え方
- 範囲: 時価総額 500 億円以上の内国株（J-Quants MktCap ≥ 50,000 百万円）。資料は有価証券報告書（EDINET docTypeCode 120）の直近 3 期。非ゴール= X での先行シグナル探索・売買判断・記事化・決算短信/説明資料の全社取得
- **母集団の定義**: 2026-10-06 bars で MktCap ≥ 50,000 百万円の内国株 1,352 社。**第 1 段（本件）= センターピン台帳 977 社のうち 500 億円以上の 962 社**（bars に無い 5・500 億未満 10 を除外・レビュー A 実測）。台帳外の約 390 社は本件では足さない（既存の TOP1000 関門が広がるため・別裁定）。「売る物がない」業種（金融/不動産/サービス等）は `products_status=物なし` で行を残し埋まり率の分母から除く
- 終了時に照合する実測項目: 〈対象社数（962）／有報を取得できた社数／`products_status=済` の社数／遡り検証に使えた社×期の数〉

## Goal

会社ごとに「何が売れると（品切れになると）利益が増えるか」を、嘘がつきにくい有価証券報告書から KPI の言葉で取り、センターピン台帳に列として足し、その KPI の好転が過去 3 期で株価に効いたかを遡って測る。

## 成功基準

- [ ] 埋まり率: （対象社 − 物なし）のうち「品目＋KPI 名＋出所（docID・要素 ID）」の 3 つが揃った社の割合 ≥ 80%（叩き台 30〜50 社の段階でも同じ式）
- [ ] 遡り検証: 期 t の通期決算短信の開示日（J-Quants fins の DiscDate）の翌営業日を起点に、+20／+60 営業日の TOPIX 超過リターンを処置群（需要かつ KPI 好転の社×期）と比較群（同じ KPI を測れて好転なし）で出す。合格線（凍結）= +60 営業日の勝率差 ≥ 10pt かつ処置群 ≥ 30 社×期・企業内反復を考慮した信頼区間を併記。別物差しとして「KPI +5% の期に区分利益が増えた割合」も出す
- [ ] 既存スクリプトが実台帳で壊れない: 列追加後に `python3 scripts/x_shortage_map.py`（自己検証）・`python3 scripts/trend_stock_screen.py`・`python3 scripts/gen_center_pin_types.py`・`x_mention_dict` の load を実台帳で実行して全部 exit 0（unittest は center_pin の実台帳を読まないので検証にならない・レビュー A5）。加えて一括ゲート `docker compose run --rm -v "$PWD/tests:/app/tests" xstock python -m unittest discover -s tests` も全件 PASS
