## 2. シグナル定義（完全指定・R1ブロッカー3対応）
- **正規化関数（凍結）**: 表題は `unicodedata.normalize("NFKC", title)` 後、空白・改行を除去して判定。
  大文字小文字は NFKC 後にそのまま（regexは大小両対応で記述）。表題欠損＝非該当。
- **regex（文字列として凍結・評価順も固定）**:
  1. `TOB_ANY = 公開買付|ＭＢＯ|MBO|マネジメント・バイアウト`（NFKC後は `公開買付|MBO|マネジメント・バイアウト`）
  2. `SELF = 自己株` … TOB_ANYマッチかつSELFマッチ→**自己株TOB＝除外**
  3. `WITHDRAW = 撤回|中止|不成立|買付.*行わない|見送り` → 除外（かつdealの破談フラグ）
  4. `PROGRESS = 結果|終了|状況|応募|訂正|変更|延長|経過` → 除外（経過系）
  5. `QUALIFY = 開始|意見表明|賛同|実施|ＭＢＯ|MBO|マネジメント・バイアウト` → 上記1〜4を通過した上でマッチ＝**適格**
  評価順: TOB_ANY→SELF→WITHDRAW→PROGRESS→QUALIFY（全て NFKC 後の表題に適用）。
- **deal_id（凍結）**: 銘柄コード（5桁正規化）単位で、**TOB_ANYマッチ全開示**（除外開示も含む）を時系列に並べ、
  直前のTOB_ANY開示から**暦日差 > 90日**（`>90`・91日以上）なら新deal。窓の更新はTOB_ANY全開示が行う。
- **エントリー対象**: deal内で**時系列最先行の適格開示1件のみ**（dealの開始が除外開示でも、その後の
  最先行適格開示がシグナル。同一dealで2度目以降の適格開示ではエントリーしない）。
- **シグナル日T（凍結）**: 開示時刻はTDnetインデックスの公式 pubdate（JST・分粒度）。
  `pubdate < 15:00:00` → T=開示日D／`pubdate >= 15:00:00`（15:00:00ちょうどを含む）または D が非営業日 → T=Dの翌営業日。
- **境界ケースのgolden test**: 実装時に代表12ケース（15:00丁度・全半角MBO・90日丁度・91日・
  除外開示が窓を更新するケース等）のテストを同梱し、テストファイルのsha256を凍結記録に含める。

## 3. PIT運用（R1ブロッカー4対応）
- **日次ラン（凍結）**: 毎朝 **07:15 JST**（寄付前）に `tdnet_index_fetch.py --recent 7` を実行し、
  **その時点で観測済みの開示のみ**でシグナル判定。判定時刻・原レスポンスsha256を追記専用で記録。
- **注文締切**: 07:15ラン＝当日寄付にエントリーする唯一の機会。API遅延等で締切後に観測された
  過去開示は **`operational_missed` として記録し、遡及エントリーしない**（--recent 7 は欠測の可視化用）。
- **欠測の正式な帰結（R2ブロッカー1・凍結）**: 欠測日=「07:15ランが成功しなかった日」または
  「本来の注文締切より後に初観測された適格開示」。operational_missed の deal は
  **保存済みインデックスと bars から仮想リターンを事後計算できる**（entry=本来のT+1寄付・exit=+20bd終値）。
  最終判定は次の**両方**を満たして初めて合格:
  (i) ベースライン（missed除外）で§5の合格条件を満たす
  (ii) **全包含感度**（missedを仮想リターンで含めて再計算）でも合格条件を満たす
  さらに **missed が前向き期間の適格dealの10%を超えた場合は窓失効**＝判定不能としてα消費済みで閉じる
  （§6付記IIの欠測感度・窓失効の規律に整合）。一時停止期間中の開示も missed として同規則で扱う。
- 副系統: EDINET公開買付届出書との日次突合で欠測検知（シグナル定義には使わない・運用監視のみ）。

## 4. 執行仕様（ペーパー・R1ブロッカー5/6対応）
- **これは日足価格による仮想約定である**（板・特別気配は観測しない）ことを明記。
- **約定状態表（凍結）**: T+1のbarについて

  | `Vo=0`（寄らず・売買停止） | **不成立** `unfilled_no_volume` |

- **検定母集団（凍結・R1ブロッカー5の解消）**: **合格判定は「成立した全deal」を1 deal=1観測の等ウェイトで行う**。
  同時保有上限・資金制約は**判定に用いない**（下記の参考ポートフォリオ列でのみ適用）。
  ＝どのdealを「選ぶ」自由度が判定に入らない。
- **参考ポートフォリオ列（判定外・運用感覚の把握用）**: 固定想定元本1,000万円・1件=min(元本の1/7,

  ※中間チェックの累積DD（§5(b)）は**deal系列の順序依存な診断統計**であり、ポートフォリオDDではない。

## 5. 判定計画（R1ブロッカー1/2/7対応・逐次検定なし・延長なし）

  （選択的報告の禁止。中止で分母から消えることはない）。
- **標本cutoffの一意化（R2ブロッカー2・凍結）**:
  (a) 前向き開始 = `prospective_start_date`（登録行に記載の暦日）。
  (b) 24ヶ月cutoff = start の24ヶ月後の同日（暦日）。**「entry予定日（T+1）≤ cutoff」の全dealを対象**とし、

  (c) n=150到達型 = 成立dealの累計が150に達した日の**entry日と同日の全dealを包含**（150で切らない）。
  (d) 判定の実施は**対象全dealの出口（20営業日）が成熟した後**。最低12ヶ月経過は(b)(c)いずれにも適用。

  以下のいずれかで**早期失敗（α消費・終了）**:

  (b) deal系列累積和（等ウェイト1単位/deal・時系列）の最大ドローダウン < −15%

- **最終判定（唯一・延長なし）**: **開始24ヶ月後 または 成立deal n=150 到達の早い方**
  （ただし最低12ヶ月経過後）。結果は 合格／不合格 の2値のみ。**「判定不能→延長」は存在しない**
  （検出力不足で不合格となるリスク＝真のEVが歴史の2/3以下なら検出できない、を**受容した上での賭け**と明記）。
- **合格条件（AND・凍結）**:

  (2) **上位5deal除外後の平均net > 0**（正式なAND条件・宝くじ排除）
