## 凍結仕様（実行前に固定・Codex MAJOR 8件反映）

- **イベント抽出**: `data/tdnet/index/` から正規表現 `(月次|既存店).*(売上|業績|速報)` に一致する開示。
  期間 2016-07〜2026-06。重複キー=`(company_code, pubdate日付, title)`。抽出式はこの1本で固定（「等」の拡張禁止）
- **反応日G**（MAJOR-3対応）: 既存 canonical 規則（`kpi_pead_signals.py` の reaction_day）を再利用 —
  2024-11-04以前は15:00以降・以降は15:30以降・時刻不明は**翌営業日**。leaderリターン= C(G)/C(G-1) − TOPIX同区間
- **leader除外**（MAJOR-4対応）: 同一leader・同一反応日Gに〈決算短信/業績予想修正/配当予想修正/M&A・TOB・増減資〉の
  開示が併発する場合は**イベントごと除外**（tdnet index のタイトル正規表現で機械判定・除外式も凍結時に固定）
- **方向の代理**: leader超過リターン **+2%以上=ポジ／−2%以下=ネガ／中間=不使用**。
  ⚠️ ±2%は既存凍結値の再利用ではなく**本計測の仮置き**（R1指摘のとおり earnings_spillover の leader は
  sales_beat であり自己株価ではない）。感度=±3%を記述併記（判定には使わない・表示のみ）
- **ターゲット**（MAJOR-5/6対応）: **PIT**で構成 — G以前の直近月末 master の**同一S33業種** ∩ Gより前の
  確定月次 **TOP500ユニバース**（`output/base_rate/universes_w21`・PIT rank）。center_pin台帳は使わない。
  同業定義は**PIT S33一本で固定**（=「粗い同業の記述」と限定・結果を見て狭い定義に切り替えるのは禁止）
- **ターゲット除外**（MAJOR-7対応）: leader自身／同一Gに自社の月次開示・決算系開示を出したターゲット
- **エピソード統合**（MAJOR-7対応）: 同一G×同一S33の複数leaderは**1 industry-day エピソードに統合**
  （方向はleader超過リターンの平均で決定・全leaderの方向が割れたら不使用）
- **測定**（MAJOR-9対応）: 起点=**G+1営業日の寄付**・終点=**+20営業日の終値**（+5は診断表示のみ・判断に不使用）。
  TOPIXも同一執行点・単純差・コスト控除なし（記述のため）。ストップ高で寄れない/売買停止/上場廃止は
  当該銘柄を除外し除外数を報告。エピソード値=ターゲット群の等ウェイト平均
- **不確実性の表示**（MAJOR-8対応）: **calendar-monthブロックbootstrap**（同一暦月の全エピソードを一括再標本・
  月等ウェイト・n_boot=5000・seed=20260809）で片側90%/95%区間を**記述として**表示
- **読み方の3値**（MAJOR-10対応・事業判断の目安・判定効力なし）:
  - `supported`: ポジ群+20日超過の点推定 ≥ **+0.30%** かつ 月クラスタ片側95%下限 > 0
  - `unsupported`: 区間が十分狭いのに点推定 < +0.30%
  - `underpowered`: 区間が広く結論不能（有効月数<24 or クラスタSEが点推定超）
  - +0.30%は「配管投資（前向き90日）に値する最低実質効果」の**仮置き**（根拠数字なし・事業判断の目安）
- **事業判断への翻訳**（凍結）: `supported`→Bの帰属ペア・ゲート（前向き90日）の起案へ進む資格／
  `unsupported`→「不足の指標化」レーンは起案せず終了／`underpowered`→データ蓄積待ちで凍結（追加掃引はしない）

### 補完1: leader除外の正規表現（仕様は「除外式も凍結時に固定」と書いたが式が記録されていなかった）

仕様本文の列挙〈決算短信／業績予想修正／配当予想修正／M&A・TOB・増減資〉に**忠実に**、以下で固定する。

```
決算短信                : 決算短信
業績予想修正            : 業績予想.{0,8}(修正|変更)
配当予想修正            : 配当予想.{0,8}(修正|変更)
M&A・TOB               : 公開買付|株式交換|株式移転|合併|子会社化|株式の取得|事業譲渡
増減資                  : 募集株式|第三者割当|新株予約権|自己株式の(取得|消却)|資本金.{0,6}(減少|額の減少)
```

- 「剰余金の配当」は**入れない**（通常の配当発表であり「配当予想の修正」ではない。広く取ると
  除外が過剰になり母集団が痩せる）
- 「株式分割」は**入れない**（資本金が動かず増減資ではない）。列挙に無い語を足さない原則を優先
- ターゲット側の「自社の月次開示・決算系開示」判定にも同じ式＋イベント抽出式を用いる

### 実行の経緯（1回目は破棄）

1回目の完走後、実装後レビュー（Codex gpt-5.6-sol）で **BLOCKER 1件＋HIGH 4件＋MEDIUM 3件＋LOW 1件**の
**仕様不一致**が判明したため、1回目の数値は破棄。**仕様は一切変更せず実装のみ修理**して再実行した
（v2 の「バグ修正の再実行は可」に該当）。修理の内訳:

| 重大度 | 実装の誤り | 修理 |
|---|---|---|
| BLOCKER | **非営業日開示で反応日Gが二重にずれていた**。土曜16:00を「月曜16:00の開示」と読み替え「引け後→火曜」にしていた（土日に引けは無い） | 非営業日は時刻を再解釈せず直後の営業日をGにする（`reaction_day_for`）。営業日は canonical のまま |
| HIGH | 終点が **G+21** になっていた（「+20営業日」は起点「+1営業日」と同じG基準） | 終点=G+20・診断=G+5 |
| HIGH | **UL/LL（値幅上限/下限への到達フラグ）で除外**していた。到達≠寄付不成立で、強い銘柄と弱い銘柄を両端から削り分布を縮めていた | 除外は寄値不在・出来高ゼロのみ |
| HIGH | 同一企業が同一Gに複数の一致タイトルを出すと**複数leaderぶんの重み**を持っていた | leader を `(code, G)` で一意化（イベントの重複キーは仕様どおり title 込みで維持） |
| HIGH | 「方向が割れたら不使用」を±2%分類で見ており、**+5%と−1%の組が採用**され平均+2%でポジ群に入っていた | 生の符号（0基準）で一致判定 |
| MEDIUM×3 | TOPIX欠損の除外数が他と混在（補完2の要求を満たせない）／上場廃止と取得欠損が同扱い／3値の優先順位が仕様に無い | 除外理由を分離／`exit_missing_delisted_or_code_change` と `..._data_gap` に分割／**supported条件とunderpowered条件の真偽を併記**し単一ラベルに依存させない |
| LOW | bootstrap 分位点の off-by-one | nearest-rank（`ceil(p*n)-1`）に固定 |

Codex が「準拠」と認めた主要点: **TOP500ユニバースに look-ahead なし**（`month < G月` は厳格な前月ルール・
生成元 `measure_base_rate.py` まで遡って確認）／master の月末スナップショット扱い／イベント抽出式と重複キー／
leader除外の正規表現（補完1と文字列一致）／価格式（`AdjO`→`AdjC`・TOPIX O→C の単純差）／
bootstrap 設計（月ブロック・等ウェイト・5000回・seed=20260809）／単一leaderが誤除外されないこと。
