起点: 2026-08-15 に発覚したベースレート誤用（9.5%=過熱3ヶ月ローカル値 → 正=4.1% catalog §6・
全期間118ヶ月 n=58,497）。誤基準で2026-08-02に「入場ゲートを越えるイベントは無い」と判定した
17イベントを、正しい基準で測り直す。ユーザー裁定 A（2026-08-16）。

## 位置づけ

**記述測定のみ**（`output/tdnet/event_profile.md` と同格）＝ **α非消費・trials.jsonl 不算入・
screening_batches.jsonl 不算入・verdict を持たない**。ゲート通過候補が出ても、それは
「§7-* 事前登録に**進める資格がある**」という意味であって合格ではない。

## 凍結仕様（測定前に固定・測定後の変更禁止）

1. **対象**: `scripts/tdnet_event_profile.py` の PATTERNS 全17イベント（**事後の絞り込み禁止**＝
   良い数字が出たものだけを残す選択をしない。全件を同じ手順で測り表に載せる）
2. **母集団**: TOP500・既存 event_profile と同一（表題マッチ＋ NOISE_EXCLUDE ＋ 同日重複排除）
3. **アウトカム**: 既存と同一（開示15時以降は翌営業日をT／T+1寄付買い→20営業日後終値・往復0.3%控除・
   hit20 = gross>=0.20 の終値判定）
4. **ベースレート**: **4.1%**（catalog §6 確定値・終値+20%/20bd・2016-08〜2026-05・n=58,497）。
   高値タッチ版 8.5% は**使わない**（判定方式が違うため）
5. **lift の信頼区間**: 既存 Canonical の `kpi_event_study.bootstrap_lift_ci` を再利用（**独自実装禁止**）。
   月ブロック・ブートストラップ・**n_boot=2000・seed=42**・両側95%CI。
   ベースは固定値4.1%（月別ベースレートを使う版が Canonical にある場合はそちらを正とし、
   どちらを使ったかを報告に明記）
6. **入場ゲートの機械適用**（catalog §0 枠S/枠F・**閾値は既存のまま・変更禁止**）:
   - 枠S: lift CI下限 ≥ 1.2 ∩ EV(stop8) ≥ +1% ∩ 年6件以上
   - 枠F: EV(なし)CI下限 > 0 ∩ lift > 1.0 ∩ 月5件以上
   - **頻度は実測**（TOP500内の年間発火数を期間で割る・推定値の流用禁止）
7. **報告義務**: 全17イベントの n / 到達率 / lift点推定 / **lift CI** / EV(なし) / EV(stop8) /
   年間頻度 / 枠S・枠F の合否を1表に。**ゲート不通過も全部載せる**（都合の良い抜粋の禁止）
8. **やらないこと**: 閾値探索・条件の後付け（サイズ条件・銘柄フィルタ等の追加）・
   期間の切り出し・イベントの新規定義。これらは全て「新しい試行」であり本測定の範囲外

## 予言（測定前に記録）

lift 点推定 2.37 の株式分割でも、**CI下限が1.2を割る可能性がある**（表題マッチは対象が広く分散が大きい）。
通過するとすれば n が大きく EV も正の「株式分割」「TOB意見表明」。暗号資産（lift 3.22）は n=447 と
小さくテーマ集中の疑いがあるため CI が広く落ちる公算。**枠S/枠F ともに通過0本**も十分あり得る。
