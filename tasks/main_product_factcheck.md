# 主力商材の全社一覧を決算で確かめる（値上がりで儲かる売り手か）

- Phase: P-INF-56（2026-10-14 オーナー「a」）。親= 主力商材の台帳 `data/center_pin/center_pin.jsonl`（977 社）と T31 の確かめ済み 213 社（`output/yuho_presign_window/t31/verdict_final.csv`）
- 裁定: 2026-10-14 オーナー「a」＝残り 764 社も T31 と同じ方法（有報のセグメント情報）で確かめてから、全社を書き出す

## 答える問い

オーナーの原文: 「どの商材が売り、上がれば株価があるかのメイン商材を全て書き出して終了にします。例えば、以前MDを見たときに異なる商材が入っていたので、そこのファクトチェックをしたいのですが、どうすれば良いですか？」→「a」。会社ごとに「主力の商材は何か・それを売って儲けている側か・台帳に書いた商材は合っているか」に答え、全社の一覧を書き出す。

## 対象と数え方（結果を見る前に決める）

- **母集団**: `center_pin.jsonl` の 977 社。うち T31 で確かめ済みの 213 社は T31 の判定を引き継ぎ（やり直さない）、残り 764 社を今回確かめる。
- **資料**: 各社の最新の有価証券報告書（EDINET の XBRL CSV・`scripts/yuho_fetch.py` の部品で取る・`data/edinet/yuho/<code>/`）。取れない会社は「資料なし」と記録し、調査役が Web の決算短信・説明資料で補う（出所 URL を書く）。
- **利益の割合（機械で計算）**: 報告セグメントのセグメント利益（有報が使う利益の物差しのまま）を使い、赤字のセグメントは 0 として、各セグメントの利益 ÷ 黒字セグメントの合計。最大のセグメントを「主力事業」とする。
- **調査役の判定（有報の本文を読む）**: 会社ごとに次を書く。
  1. 主力商材: 主力事業が主に売っている物の名前（物を売らない会社は「商材型でない」と書き、利益を決める物＝金利・既存店売上・受注など を書く）
  2. 台帳の商材（center_pin の pin）を売っている事業と、その利益の割合
  3. 値上がり・品薄の時に、その会社の売値か販売数量が上がるか＝売り手／買い手（原価側）／どちらでもない
  4. 台帳の判定: **はい**＝割合 30% 以上かつ売り手／**保留**＝10〜30% かつ売り手／**いいえ**＝10% 未満、または買い手／**商材型でない**＝台帳の pin が物でない（金利・為替・既存店売上・稼働率など）／**判定不能**＝資料で確かめられない
  5. 単一セグメントの会社: 事業の内容で台帳の商材が唯一または主（過半と書かれている）なら割合 100% 扱い、内訳が書かれていなければ「保留（内訳非開示）」
  6. 根拠: 出所（有報の docID か URL）・年度・数字を 1〜2 行
- **独立の検証役**: ① セグメントの割合を sections.json から別の計算で出し直して全社照合 ② 無作為の 40 社と「いいえ」全件の判定を本文で読み直す。
- **件数の突合**: 渡した 764 社／資料が取れた社／判定が返った社を報告する。
- **書き出し**: vault に全 977 社の一覧（会社・主力商材・割合・売り手か・台帳の判定・出所）と、「はい」の会社だけの一覧。
