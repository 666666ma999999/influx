### v2 の正式合格（AND・3つ全部満たした時だけ「正式合格」）

1. **v1（不変・記録）**: 系統別対応表の「v1 条件」列そのまま。計算細部は凍結文に無いので本版で固定する（「v1 側の計算細部の固定」）。**v1 の判定はこれまでどおり計算・記録し、v2 の判定とは別欄に出す**

3. **対TOPIX超過EVの頑健条件（v2 新設）**: 超過（下の式）の1日1票に同じ器を当て、**片側 p ≤ その系統の α_eff**

### v1 側の計算細部の固定（T0・本版と同時に固定・R2 の固定内容を維持）

凍結文は v1 の集計単位・中心化の有無・n_boot・seed・CI 方式を書いていない（前向き正式判定の実装も無かった）。R2 で固定した内容をそのまま維持する（R3 で頑健 t に差し替えたのは撤回）。

- 共通: 対象行 R の各行の値 `v_i = ret_nostop_i`（往復 0.3% 控除済み）→ 日票 `x_d = mean(v_i : signal_date=d)` → 点推定 `X = mean_d(x_d)`。ブロック = **票のある暦月**（空月はブロックにしない）。有効月数 M = その数。再標本 = 月ブロックを M 個復元抽出し、抽出月内の日票を**連結した平均** `X*`。`n_boot=20000`・`seed=20261004`
- **§7-Q・§7-T・§7-W・§7-Y・§7-AB（「片側 p ≤ α」型）**: 帰無中心化（§7-K の書式に揃える）。`x_d − X` で再標本し `p = (1 + #{X* ≥ X}) / (n_boot + 1)`、MCSE 併記。**境界規則**: `|p − α| < 2·MCSE` のときだけ同じ seed で `n_boot=200000` に1回だけ増やして確定
- **§7-J SUE 2系統（「95%CI 下限>0」型）**: 非中心化 percentile。`x_d` のまま再標本し、昇順で 0 始まり `floor(0.025·n_boot)` 番目を下限とする。下限 > 0 で充足
- **最低有効月数**: M < 6 なら v1 未達で確定（quiet は Q7 の 24）
- **lift 点推定**: `lift = (Σ hit_i / N) / (Σ_m n_m·b_m / Σ_m n_m)`、`hit_i = 1[ret_nostop_i + 0.003 ≥ 0.20]`（gross 判定）・m = signal_date の暦月・n_m = その月の R の行数・b_m = TOP500 の同月ベースレート（`scripts/measure_base_rate.py` の月次コホート）。b_m が引けない月があれば TOPIX 欠損と同じ保留→20営業日で失効
- **頻度**: 分子 = R のうち signal_date が正式窓の coverage-qualified 完全暦月にある行数、分母 = その月数（D-17・§7-J の「完全に経過した暦月」）。月5件 = `≥5.0`、年6件 = `≥0.5/月`
- **中間判定（早期棄却のみ・既存どおり）**: confirmed n≥30 または 3か月経過の早い方で1回。v1 値の月次ブロック bootstrap（非中心化 percentile）95%CI 上限（昇順 `n_boot−1−floor(0.025·n_boot)` 番目）< 0 なら早期棄却。M < 2 で計算できなければ早期棄却しない。quiet は Q6（3か月の枝に有効月≥6）
- v1 の器のサイズは保証されない（T0b 第1段）。**v1 は「凍結文の線を記録する欄」であり、合格の誤り率の保証には使わない**

### 頑健条件の器（v2 の条件 2・3 で共通・T0b で確定）

- 対象行 R・日票 `x_d`・点推定 `X` は v1 と同じ作り方（条件 2 は `v_i = ret_nostop_i`、条件 3 は下の超過）
- **連続2か月クラスタ**: signal_date の暦月を、窓の初月 2026-08 を起点に2か月ずつ束ねる（`k = floor((月番号 − 2026-08 の月番号)/2)`＝8-9月・10-11月・…。2026-07 は単独のクラスタ −1）。G = 票のあるクラスタ数
- **クラスタ頑健標準誤差（CR1）**: クラスタ g の残差和 `e_g = Σ_{d∈g}(x_d − X)`、`V = G/(G−1) · Σ_g e_g² / D²`（D = 日数）、`SE = √V`
- **片側 p** = `P(T_{G−1} ≥ X/SE)`（自由度 G−1 の t 分布の上側確率・帰無「平均 ≤ 0」）。SE=0 のときは X>0 なら p=0、X≤0 なら p=1
- **判定**: p ≤ α_eff（系統別・下表）。**最低有効月数**: M < 6（quiet 24）なら未達で確定（M ≥ 6 なら G ≥ 3 が自動で成り立つ）
- 乱数を使わない（seed・n_boot・境界規則は不要）。表示用の片側95%下限（`X + t_{0.05,G−1}·SE`）は診断値で判定に使わない
- 実装の正本 = `scripts/formal_excess_v2.py` `cluster_t` / `pvalue` / `robust_condition` / `ALPHA_EFF`

### 追加条件の計算（全部ここで固定・後から変えない）

- 行ごとの超過: `excess_i = ret_nostop_i − (TOPIX_C[exit_date_nostop_i] / TOPIX_O[entry_date_i] − 1 − 0.003)`（**TOPIX 側も往復 0.3% 控除＝確認2 裁定**）

  - exit 変種は **nostop（primary）だけ**。stop8 / e1 の超過は参考表示のみ
- 1日1票: `x_d = mean(excess_i : 系統内で signal_date = d の判定対象行)`。defer で entry 日が行ごとに違っても、各行は自分の entry/exit 日で TOPIX を引いてから平均する

### サイズ検証（T0b・凍結前に実施・前向き損益は不使用）

- **方法（全段共通）**: 14 系統それぞれの in-sample `output/kpi/<系統>/returns.csv`（in_universe 行）から絶対 `ret−0.003` と超過を作り、1日1票にして**全期間平均を引いて帰無（平均0）**にする。合成窓 = 暦月列（空月込み）から**連続 1/2/3 か月の塊**を無作為に継ぎ足す（月跨ぎの20営業日保有の依存を残す）。各窓に検定を当て、p ≤ 閾値 の率（実測サイズ）を測る
- **第1段（R2 の器＝v1 と同じ月次ブロック bootstrap・各系統 2,000 窓・3か月塊・12か月窓）**: 14 系統プール p≤α 率 — 絶対 6.33α／3.33α／1.64α（α=0.0015625／0.005／0.025）、超過 3.89α／2.05α／1.11α＝**不合格**。v1 の器は名目 α を大きく超えて「合格」を出す。これが v1 を記録欄に留め、絶対EVにも頑健条件を足す理由
- **第2〜4段（器の比較）**: 1か月ずつの窓でも bootstrap は 5.76α（＝月の依存ではなく小標本・裾の重さの問題）。studentized bootstrap 1.90〜2.13α。暦月クラスタ頑健 t は系統別で最大 2.90α → **連続2か月クラスタ**に広げた
- **第5段（2か月クラスタ t・各系統の実際の α・名目のまま・30,000 窓）**: 系統別の最大 1.84α（gap_hold_close_strong 超過・3か月塊）、engulf 1.78α、three_up 1.62α、sell_reg 1.55α。**名目 α のままでは系統別に超える**＝較正が要る。（R3 はここで「14 系統プールで合格」と書いたが、プール基準は R3 で足した基準で R2 には無かった＝Codex MUST2。R3.1 で撤回）

### 欠測・保留の終端規則

- **欠測の感度分析（§6付記II C-10）**: 同じ3シナリオから**v1・絶対の頑健条件・超過の頑健条件の全部を再計算**する（シナリオを条件ごとに変えない）
  - シナリオ1（欠測日0シグナル）: 行を足さない
  - シナリオ2（当時 snapshot から再現できたシグナル全包含）: 再現行は自分の entry/exit 日で TOPIX を引き、通常行と同じく日平均に入れる
  - シナリオ3（operational_missed を不利固定値）: 絶対側は既存定義（C-11）。超過側の不利固定値 = その系統の前向き判定対象行の**超過**を昇順に並べた `sorted[floor(0.1·(n−1))]`（下側実値・補間なし）。判定対象行 <10 のときは in-sample returns.csv の各行について同じ式で超過を作れる場合のみ代用、作れなければ**判定不能 = 窓失効**（D-14・α消費済みとして記録）
  - 不利固定値の行は、その欠測日の票として日平均に入れる（同じ日に実測行があれば混ぜて平均）
  - 3シナリオで**v2 のラベル**が割れたら §6付記II と同じく窓失効
- **TOPIX 欠損**: 判定時に1行でも TOPIX の O/C が引けなければ保留。保留の期限 = cutoff 以前の全シグナルの出口確定日から **20営業日**。期限までに J-Quants から再取得して埋まれば判定、埋まらなければ**窓失効（α消費済み・D-14）**。補間・前日値代用はしない

### 判定の順序（全系統共通・上から評価）

1. 完全性監査（§6付記II B〜D）不成立 → `window_expired`

### SUE ペア判定表（§7-J）の読み替え

- 各系統の状態を **{充足 / 未達 / 保留 / 失効}** の4つで持つ。「充足」= v1 の3条件 ∩ 絶対の頑健条件 ∩ 超過の頑健条件
- どちらかが**保留**なら、ペア判定全体を保留（片方を「未達」と見なして他方へ切り替えることはしない）。期限は上の TOPIX 欠損規則と同じ。失効は §7-J の「未達」と同じ扱い
- 比較時点 = 両系統の cutoff の遅い方。「充足/充足」時の ΔEV 比較は**絶対 ΔEV のまま**（§7-J 原文どおり・同一SUEイベント集合の月次 paired 差分）
- **書き込みと数え方の契約**: ペアが保留の間は、両系統とも trials.jsonl に正式判定行を書かない（片方が先に成熟しても、その系統の判定は計算して控えに置くだけ）。ペアが確定したら両系統の判定行を同時に書き、採択された1系統の行にだけ `sue_pair_adopted: true` を入れる。`count_formal_passes` は SUE の行を **`verdict=="formal_pass"` ∧ `sue_pair_adopted is True`** の時だけ数える＝ペアは最大1本（両方充足でも2本と数えない・片側だけ formal_pass で採択印が無い行は数えない）（実装 `sue_pair_decision`・`is_counted_formal_pass`）

### 多重検定・α の扱い

- 合格には「絶対EV≤0」と「超過EV≤0」の**両方の帰無仮説を、頑健条件で棄却**することが要る（intersection-union test）。どちらの帰無が真でも、合格の確率はその帰無に対応する頑健条件の棄却確率以下（依存の有無によらない＝包含関係）。v1 は AND の一部として合格を減らす方向にしか働かない
- **主張の強さ（2段に分けて書く）**:
  - **系統ごと**: 頑健条件の棄却確率は、**指定した合成分布（T0b 第7段の 12 変種）で名目 α からの逸脱を検査し、許容線（α＋2·MCSE）内だった**。これは**厳密なサイズ保証でも、棄却率の片側信頼上限による保証でもない**（有限回のシミュレーション・3 桁切り下げ・合成分布の選び方に依存。gap_hold_close_strong は検証で 1.05α＝許容線内だが α を超えている）。前向き窓の依存構造が合成窓と違えばずれうる（未確認7）
  - **系統をまたぐ全体**: 陣別 alpha-spending の総和 ≤0.05 は**第1陣以降の陣の系統**についての既存の設計上の配分で、チャンピオン（0.025）と SUE ペア（0.025）は陣の外の別枠（E-20）。14 系統全体の FWER ≤0.05 は**主張しない**（既存のまま・本版で変えない）。また較正は系統ごとの合成窓で行ったもので、系統間の同時分布（同じ相場で同時に外れる）は扱っていない
- **新しい α 予算は配らない**（α_eff は系統 α を下げる方向の較正のみ）
- `data/kpi_trials/trials.jsonl`: **今回の改定では行数・内容とも不変**（114 行・SHA-256 `82bbcd992be5683d302bf04130c04d7df90f5b6ec74e0ddd922a6119c262638a` を前後で一致確認）。将来の正式判定・窓失効は従来どおり**系統1回=新規1行**として追記し、その1行に v1 の結果・2つの頑健条件の結果・`pass_rule_version`・`registered_after_interim_view: true` を入れる（過去行へのフィールド追加はしない）。Bonferroni 分母（非空行数・`scripts/kpi_bonferroni_check.py`）と前向きの陣別 α は別管理のまま

## 未確認

1. **前向き正式判定の本体（ランナー）が無い**: 成熟・cutoff・完全性監査・b_m の前向き月の取得・3シナリオの組み立て・SUE の控え保管は T8。本版の計算器は「与えられた R に対する v1／頑健条件の計算とラベルの組み立て」まで

3. **検出力**: α_eff は α より小さく（系統により約半分）、2か月クラスタ化と合わせて検出力は下がる方向。raw_strev_entry は月末1回だけ発火 → 12か月で約 12 票・G≈6。検出力は未計算（効果量の仮定に成績値を使うと「成績から線を選ぶ」に近づくため出さない）
4. **TOPIX の完全性監査**: 判定時の TOPIX 完全性を日次証跡で誰が保証するかは未定（本版は判定時の入力検査と保留期限で代替）
5. ledger の価格は取得時点までの分割のみ反映（メモリ「J-Quants キャッシュの分割補正」）。v1・v2 共通の既知リスク
6. （解消）okasira 前向きの合格線は vault ノート §6 H1 を実読して確定
7. **サイズ検査の範囲（保証ではない）**: 合成窓（in-sample の帰無中心化・1〜3か月の塊・窓長 12/18〔quiet 89/36〕・先頭部分月あり/なし）での実測。前向き窓の実際の依存構造・成熟延長（n≥100 待ちで窓が 18 か月を超える系統）・系統間の同時分布は再現していない
