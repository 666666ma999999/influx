### v2 の正式合格（AND・全部満たした時だけ「正式合格」）

2. **追加条件（v2 新設）**: **対TOPIX超過EV（1日1票）の片側 p ≤ その系統の α**（E-20 の値。第2陣は丸め値でなく `0.0125/3` を計算に使う）。**超過側の α を系統 α より緩くすることはしない**（緩めると「絶対EVは十分正・超過はゼロ」の系統を系統 α を超える確率で合格させてしまうため）

### 追加条件の計算（全部ここで固定・後から変えない）

- 行ごとの超過: `excess_i = ret_nostop_i − (TOPIX_C[exit_date_nostop_i] / TOPIX_O[entry_date_i] − 1 − 0.003)`（TOPIX 側も往復 0.3% 控除＝オーナー裁定 2026-10-04・Q1 の裁定行）
  - 両側とも**価格リターン（配当なし）**。ledger は AdjO/AdjC のみで配当加算をしていない（`paper_eval.py` に配当処理なし・実測）。catalog L340「配当加算」規約との不一致は v1 にも共通の既存問題として未確認2に記録し、本版では両側を価格リターンで揃える
  - `ret_nostop` は往復コスト 0.3% 控除済み（既存規約）。TOPIX 側も同じ往復 0.3% を控除する（2026-10-04 裁定で確定・旧既定値「引かない」は失効）
  - exit 変種は **nostop（primary）だけ**。stop8 / e1 の超過は参考表示のみ
- 1日1票: `x_d = mean(excess_i : 系統内で signal_date = d の判定対象行)`。defer で entry 日が行ごとに違っても、各行は自分の entry/exit 日で TOPIX を引いてから平均する
- 点推定: `X = mean_d(x_d)`（日の単純平均）
- p 値: **帰無中心化・暦月ブロック bootstrap**
  - ブロック = signal_date の暦月のうち**票が1つ以上ある月**（空月はブロックにしない）。有効月数 = その数
  - 再標本: 中心化系列 `x_d − X` を月単位で復元抽出（抽出月数 = 有効月数）し、抽出された月内の日票を**連結した平均**を `X*` とする
  - `n_boot=20000`・`seed=20261004`・`p = (1 + #{X* ≥ X}) / (n_boot + 1)`・Monte Carlo 標準誤差（MCSE）併記
  - **境界規則**: `|p − α| < 2·MCSE` のときだけ、同じ seed で `n_boot=200000` に1回だけ増やして再計算し、その p で確定。seed の変更は禁止
  - **最低有効月数**: 有効月数 < 6 のときは超過条件「未達」で確定（保留にして後で判定し直すことはしない）
  - 20営業日の保有は月境界を跨ぐため、月ブロックは近似である。**凍結前に帰無シミュレーションでサイズ（第一種の誤り率）を検証する**（タスク T0b）。合格線: 最小 α=0.0015625 で実測サイズ ≤ 1.5α。超えたら凍結を止めて本節を再設計（ブロック長を2か月にする等は**その時点で**再レビュー）
- 表示用に片側95%下限（非中心化 bootstrap の 5% 点）も**診断値として**併記する。判定は p のみ。両者は双対ではなく α も違うため、食い違いうることを表示に注記する
- 入力検査: TOPIX の O/C が有限・O>0・日付重複なし。判定時の ledger / topix の SHA-256 と TOPIX 取得時刻を判定行に保存

### 欠測・保留の終端規則

- **欠測の感度分析（§6付記II C-10）**: 同じ3シナリオから**絶対側と超過側の両方を再計算**する（シナリオを条件ごとに変えない）
  - シナリオ1（欠測日0シグナル）: 行を足さない
  - シナリオ2（当時 snapshot から再現できたシグナル全包含）: 再現行は自分の entry/exit 日で TOPIX を引き、通常行と同じく日平均に入れる
  - シナリオ3（operational_missed を不利固定値）: 絶対側は既存定義（C-11）。超過側の不利固定値 = その系統の前向き判定対象行の**超過**を昇順に並べた `sorted[floor(0.1·(n−1))]`（下側実値・補間なし）。判定対象行 <10 のときは in-sample returns.csv の各行について同じ式で超過を作れる場合のみ代用、作れなければ**判定不能 = 窓失効**（D-14・α消費済みとして記録）
  - 不利固定値の行は、その欠測日の票として日平均に入れる（同じ日に実測行があれば混ぜて平均）
  - 3シナリオで**v2 合否**が割れたら §6付記II と同じく窓失効
- **TOPIX 欠損**: 判定時に1行でも TOPIX の O/C が引けなければ保留。保留の期限 = cutoff 以前の全シグナルの出口確定日から **20営業日**。期限までに J-Quants から再取得して埋まれば判定、埋まらなければ**窓失効（α消費済み・D-14）**。補間・前日値代用はしない

- 成熟（confirmed n≥100 または 12完全暦月の遅い方・bull/bear 各≥1）・cutoff（D-15）・各系統1回だけ判定・中間（n≥30 or 3ヶ月）は**絶対EVによる早期棄却のみ**（超過での早期棄却は新設しない）

### SUE ペア判定表（§7-J L1305-1314）の読み替え

- 各系統の状態を **{充足 / 未達 / 保留 / 失効}** の4つで持つ。「充足」= v1 の3条件 ∩ 追加条件
- どちらかが**保留**なら、ペア判定全体を保留（片方を「未達」と見なして他方へ切り替えることはしない）。期限は上の TOPIX 欠損規則と同じ。失効は §7-J の「未達」と同じ扱い
- 比較時点 = 両系統の cutoff の遅い方。「充足/充足」時の ΔEV 比較は**絶対 ΔEV のまま**（§7-J 原文どおり・同一SUEイベント集合の月次 paired 差分）
- 計数: ペアから採択された**1系統だけ**を正式合格1本と数える（両方充足でも2本と数えない）

### 多重検定・α の扱い

- 合格 = 「絶対EV≤0」と「超過EV≤0」の**両方の帰無仮説を、それぞれ系統 α 以下で棄却**した時だけ（intersection-union test）。両検定がそれぞれ α 以下なら、依存の有無によらず AND 判定の誤りも α 以下＝**系統の α は増やさず、新しい α 予算も配らない**
- 保証の範囲: 陣別 alpha-spending の総和 ≤0.05（catalog L1953-1963）は**第1陣以降の陣の系統**についての保証。チャンピオン（0.025）と SUE ペア（0.025）は陣の外で別枠（E-20）であり、14 系統全体の FWER ≤0.05 は主張しない（既存のまま・本版で変えない）
- `data/kpi_trials/trials.jsonl`: **今回の改定では行数・内容とも不変**（114 行・SHA-256 `82bbcd99…2638a` を前後で一致確認）。将来の正式判定・窓失効は従来どおり**系統1回=新規1行**として追記し、その1行に v1 と v2 の両結果を入れる（過去行へのフィールド追加はしない）。Bonferroni 分母（非空行数・`scripts/kpi_bonferroni_check.py:54`）と前向きの陣別 α は別管理のまま
